# ADR-001: Modular Monolith and Evidence-First Deal State

- **Status:** Proposed; Product Owner approval pending
- **Date:** 2026-11-19
- **Decision owners:** Product Owner and Principal Architect

## Context

The seven-day build must cover ingestion, retrieval, negotiation state, reconciliation, agent investigation and human review. Microservices, streaming infrastructure and a graph database would add operational risk without demonstrated need. The domain has a correctness hazard: an LLM may mistake a proposal, acknowledgement or ambiguous phrase for acceptance.

## Proposed decision

1. Use a modular monolith for API and domain modules.
2. Use PostgreSQL as system of record; model relationships with normalized tables, foreign keys and append-only event history.
3. Use pgvector only after verifying deployment support and dimensions; hide semantic search behind a repository interface.
4. Preserve original evidence as immutable files with SHA-256 checksums.
5. Store extractions as provisional assertions with exact source locations and model/prompt provenance.
6. Derive candidate terms with a deterministic, versioned state reducer.
7. Limit agent autonomy to bounded retrieval, investigation and clarification drafting.
8. Require human review for ambiguous or high-impact state changes.
9. Disable external side effects in the MVP.

## Alternatives considered

- **Microservices:** rejected for MVP; no proven independent scaling/ownership need.
- **Dedicated graph DB:** deferred; relational edges suffice for a single-deal event graph.
- **LLM as source of truth:** rejected due non-determinism and weak explainability.
- **Fully autonomous agent:** rejected due risk of sending messages, approving payments or filing claims.

## Consequences

Positive: faster local setup, simpler end-to-end testing, provenance and deterministic state semantics, no hidden side effects.

Negative: requires modular discipline; pgvector compatibility must be tested; human review limits autonomy but improves trust.

## Revisit when

Official problem brief changes architecture needs; measured workload requires separate worker scaling; production multi-tenant needs are proven; or permitted DB lacks vector capability.
